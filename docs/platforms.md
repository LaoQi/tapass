# 运行平台与资源约束

本文记录 tapass 已支持 / 规划中的运行平台及其资源约束。资源约束直接影响
KDF（Argon2id）参数选择与 vault 文件的可移植性。

## 平台矩阵

| 平台 | 形态 | 状态 | 资源约束 | 备注 |
|------|------|------|----------|------|
| Linux x86_64 | 桌面 / 服务器（CLI、TUI） | 已支持 | 无特殊约束 | CI 构建 `linux/amd64`；默认参数 m=16 MiB |
| Windows x86_64 | 桌面（CLI、TUI） | 已支持 | 无特殊约束 | CI 构建 `windows/amd64` |
| 嵌入式 Linux SoC | 设备本地保管库 | 规划 / 使用场景 | **物理内存约 64 MiB，可用内存可低于 32 MiB** | 能否解析取决于本机可用内存，见下节 |
| Android | 移动客户端 | 规划（todos.md） | 待确认 | 依赖二进制格式冻结 |

其他平台（macOS、arm 系列、BSD 等）尚未确认，暂不列入。

## 嵌入式设备的内存约束（关键约束）

- Argon2id 的解析峰值内存 ≈ 头部 `memory` 参数（KiB）。
- 默认参数 `m=16 MiB` 在"可用内存 < 32 MiB"的设备上已接近极限（还需 Go 运行时与程序本体的开销）。
- 由此确定的实现原则：
  1. vault 头部记录 KDF 参数，任何设备打开时**以本机能力为准**判断能否解析；
  2. 本机内存不足时返回明确错误（需要 X MiB / 可用 Y MiB），不得被 OOM kill 或 panic；
  3. 不设全局参数上下限（同一 vault 在 PC 上可使用更高参数）；建库 / 改参时按目标设备的可用内存选择；
  4. 内存探测：Linux 读 `/proc/meminfo` 的 `MemAvailable`；其他平台暂不探测（能力未知时不阻拦），待补充。

## 不变量

- 头部声明的 Argon2 参数必须能被实现**精确执行**（见 `v1/crypto-model.md` 的参数约束），
  否则拒绝解析：不同实现下实际生效参数不一致会表现为"密码错误"，属于误导性失败。
- KDF 参数与已派生密钥必须始终一致；参数变更只能通过 `Rekey`（重新派生）完成。
